# Compact review goal — staged delivery

The full goal remains active until all stages, independent audits, runtime
restoration and delivery checks are finished. Small samples cannot establish
unattended reliability. A negative model result is a valid completed evaluation;
missing experiments are not.

| Part | Deliverable | State |
|---|---|---|
| 1 | Bounded exact-mutation packets, compact source-backed evidence, offline execution/admission controls and historical size measurements | Complete; [report](part1.md) |
| 2 | Timed reviewer comparison, transport/timeout and output-schema checks, detection/false-positive evaluation, cache/switch cost and selected next-stage configuration | Complete; [report](part2.md) |
| 3 | Fresh symptom-led native Hermes workflows with dependent followups, real Gitea issues/forks/commits/PRs and independent whole-workflow audit | Pending |

## Part 2

Freeze a bounded development set of buggy and correct proposals before calling
models. Keep expected findings, grader/reference and later tasks private. Cases
from the completed pilot are calibration/development data, never fresh success
claims. Compare the 27B candidate with a retained faster reviewer using identical
supplied evidence and explicitly recorded settings. Start with retained models;
no download is needed merely to begin.

Measure actual rendered input, output limits, response schema, caller/backend
latency, delivered versus late feedback, missing capture, useful detections and
false findings. Use measured deadlines; don't call a timeout a caught defect.
Validate any constrained-output option against the pinned backend before use.
Keep packet/deadline/schema changes distinct from a model-only quality claim.

A second model may not fit beside the 27B on the P100. Verify actual VRAM and
headroom, not file size. If switching models is necessary, include load/switch
and lost actor-cache costs rather than advertising only isolated critic speed.
Do not touch Hermes-Codex. Preserve current credentials/settings/models and
at least 100 GiB model-disk reserve. Restore and verify the original runtime
before the stage's report and commit/push.

## Part 3

Choose fresh real bug cases and validate independent reproduction, preservation
controls and reference corrections before inference. Freeze tasks, evaluation,
review settings and budgets before the scored calls. Preserve normal native
persistence, memory/skill approval and real selected-checkout context. Followups
must use the same logical session; report actual compaction/retention behavior.

Use fresh paired control/full-review workflows when assessing contribution from
behavioral review. Both arms require genuine execution and an external
documentation check; the control withholds behavioral/coverage feedback. This
common safety baseline is not a pure no-review latency measurement. Give the same symptom-led requests and dependent followups across arms;
never send operator grader findings or corrective task hints to either model.
Review-generated findings are the declared treatment, not private-test feedback.
Independently inspect actual code, unchanged behavior, relevant regressions,
documentation, real execution receipts and exact remote Git trees. Correctly
placed issues/PRs or authored passing tests alone are not success.

Use disposable upstream/personal-fork arenas with configured ownership inference.
Close test issues after evidence capture, retain PRs unmerged as declared evidence,
restore/verify the original runtime, publish sanitized reproducible evidence and
commit/push. If the best justified setup still fails, report that result without
skipping the required fresh evaluation or claiming unattended reliability.
